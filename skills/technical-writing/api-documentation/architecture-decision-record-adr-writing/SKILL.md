# Architecture Decision Record Adr Writing

## Overview
Code shows how software works; ADRs explain why it was built that way. Capturing Title, Status, Context, Decision, and Consequences preserves architectural knowledge across team turnover.

## Operational Workflow

1. **Assign sequential ADR identifier**:
   - Assign sequential ADR identifier: doc/adr/0012-use-kafka-for-event-streaming.md.

2. **Document Context**:
   - Document Context: describe the architectural problem, technical constraints, and alternatives evaluated.

3. **State Decision**:
   - State Decision: articulate the chosen solution clearly in the present tense.

4. **Analyze Consequences**:
   - Analyze Consequences: list positive outcomes, negative trade-offs, and resulting operational risks.

## Recommended Tools & Environments
- ADR
- Architecture Documentation
- Technical Decision Records
- Markdown

## Verification & Execution Criteria
- Pre-execution validation verifies all prerequisites and inputs.
- Step-by-step progress logging confirms intermediate state transitions.
- Post-execution checks verify output integrity and clean exit codes.
